# ADR-002: Refunds are idempotent per invoice

## Decision

A refund is keyed by `(invoice_id, refund_id)`; replaying the same refund
request returns the original result instead of refunding twice.

## Rationale

Payment webhooks retry. Without idempotency a retried webhook double-refunds
the customer — the duplicate-charge disputes in the disputes corpus are
usually this failure, not a billing error.

## Consequence

`apply_refund` must reject a refund whose key already exists, and callers
must pass the idempotency key through. Not yet implemented in `billing.py`.
